# 发布包验收

Nikkiward 的公开分发目标包括 Windows 安装包和便携 ZIP。任何发布候选都必须使用与
GitHub Release 相同的产物完成本页验收；源码构建成功不能替代跨机器运行与渠道启动
验证。

## 产物基线

- 目标架构为 `win-x64`，应用保持 unpackaged 部署，不转换为 MSIX。
- publish 目录使用 Windows App SDK self-contained 模式，并明确关闭裁剪。
- 安装包只负责部署、升级和卸载同一份 publish 内容，不改变渠道识别与启动契约。
- 便携 ZIP 解压后无需 .NET SDK、Visual Studio 或开发者模式即可运行。
- 发布清单、ZIP 内容和校验和必须来自同一提交；必需资源缺失时停止发布。

## 系统矩阵

发布候选必须在全新或已还原快照的 Windows 10 1809 及更高版本、Windows 11 x64
环境中测试，且测试账户为非管理员标准用户。系统不得预装 .NET SDK、Visual Studio
或项目构建产物。

每个系统至少覆盖以下部署位置：

- 默认系统盘路径；
- 包含中文、空格和较长目录名的路径；
- 非系统盘路径。

安装包和便携 ZIP 都必须完成首次启动、退出、再次启动、设置保存和日志写入验证。
应用不得要求管理员权限才能执行这些日常操作。

## WebView2

在已安装 WebView2 Evergreen Runtime 的机器上，所有使用网页内容的功能必须正常
加载。在未安装 WebView2 Runtime 的干净环境中，安装流程或应用必须给出明确且可
操作的依赖提示，其他不依赖网页的页面不得因此崩溃。完成依赖安装后必须重新验证
网页功能和应用重启。

## 渠道矩阵

国服官方渠道、哔哩哔哩渠道和 Steam 国际服必须分别测试，且每项结论只适用于被
实际验证的渠道。安装器不得把一份游戏内容推断为已经具备其他渠道的启动壳、认证
状态或登录能力。

每个渠道至少覆盖以下状态：

- 该渠道完整安装且所需启动组件存在；
- 游戏目录存在但该渠道组件缺失或版本不受支持；
- 该渠道完全未安装；
- 多个渠道同时存在，切换后检测、展示和启动目标不串线。

所有缺失或不受支持状态都必须保持 fail-closed，界面应说明当前缺少的组件，不得
回退到另一个渠道或把未验证链路显示为可启动。

Steam 国际服还必须覆盖 Steam 客户端未安装、已安装但未运行、正在运行但未登录、
已登录以及离线模式。需要 Steam 认证的启动仍以 Steam 客户端的实际状态为准，
Nikkiward 不替代 Steam 登录。

对每个可用渠道，验收记录必须分别包含应用发起启动、目标进程、登录界面或账号态、
进入游戏结果和退出后的状态恢复。仅看到进程创建不能记为登录或完整启动通过。

## 升级与卸载

安装包必须验证从上一公开版本升级、同版本修复安装和新版本覆盖安装。升级后应用
文件应全部来自新版本，不得混用旧 DLL 或资源；便携 ZIP 覆盖升级也必须给出明确的
关闭应用和替换边界。

用户设置位于 `%LOCALAPPDATA%\Nikkiward`。收藏保护副本等用户内容位于用户选择的
目录或用户图片目录。正常升级不得删除或重置这些数据；默认卸载也必须保留用户数据，
只有用户明确选择删除个人数据时才可清理，并应在执行前列出范围。

设置 schema 升级后，应用会保留 `%LOCALAPPDATA%\Nikkiward\settings.pre-schema6.rollback.json`
作为迁移前副本。降级到不识别新 schema 的旧版本时，安装包的回滚流程必须先验证该副本
仍可解析，再原子恢复为 `settings.json`；正常卸载和修复安装不得删除这份回滚副本。

卸载后必须确认程序文件、开始菜单入口和卸载登记已移除，同时用户数据保留符合用户
选择。随后重新安装，验证保留设置可读取且损坏或旧版本数据不会阻止应用启动。

## 通过条件

公开发布要求上述矩阵全部有可追溯结果，且安装包与便携 ZIP 均通过恶意软件扫描、
文件清单校验、首次启动、渠道缺失处理、实际渠道启动、升级、卸载和数据保留测试。
任一必需环境只有静态检查、构建结果或未经登录确认的进程观察时，该项保持未通过。
